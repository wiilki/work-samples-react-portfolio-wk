# Will Kim — Portfolio

A fully refreshed, responsive React portfolio featuring selected websites, web apps, and backend projects.

## Current design

- An editorial-style landing page with an accessible sticky navigation, featured work, searchable/filterable project archive, about, expertise, and contact sections.
- Honest project cards with meaningful descriptions, technologies, GitHub links, and live-site links **only for projects with a known public deployment**.
- Published project previews prefer locally stored **real browser screenshots** captured from live project URLs by Playwright. A pair of external screenshot services acts as fallback while the local image is unavailable. Source-only projects use labeled illustrative previews, not fabricated screenshots.
- A modern slate/navy and cobalt-blue visual system, with mobile navigation, visible focus states, skip link, reduced-motion support, semantic headings, and responsive grids.
- Source-only applications such as Paceboard are **not represented as currently live** until deployment is confirmed.

## Run locally

Node 20+ is recommended.

```bash
npm install
npm start
```

To validate the portfolio:

```bash
CI=true npm test -- --watch=false --runInBand
npm run build
```

## Updating projects and previews

Edit [src/data/projectData.js](src/data/projectData.js). Each entry requires an `id`, `title`, `subtitle`, `description`, `category`, `tags`, `repo`, and `tone`. Add a `live` field **only** when the public website is actually deployed. The card then requests a fresh screenshot from the published URL. Screenshot images are automatically generated by a third-party service, which may cache results and is not part of this repository.

Do not add private, local-only dashboards or unreleased preview URLs as public links. Live apps can change independently of this portfolio; confirm a live URL before listing it.

## Refreshing screenshots

The capture manifest is in [scripts/preview-sources.json](scripts/preview-sources.json). Keep its `id` and `url` synchronized with live projects in `src/data/projectData.js`. The capture script navigates to each published URL using Chromium and stores an actual 1440 × 900 browser screenshot at `public/previews/<id>.png`. Sites that fail to load or show an error are skipped.

The workflow `.github/workflows/capture-previews.yml` can be run manually via **Actions → Refresh project screenshots → Run workflow** on the default branch after it is merged. It commits new captures only if image content changes. It is intentionally not a scheduled workflow to avoid unnecessary build minutes. An unpublished source-only project never receives a fake 'live screenshot'.
